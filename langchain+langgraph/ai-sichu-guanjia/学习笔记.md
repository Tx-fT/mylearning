# AI 私厨管家 · 从 0 到 1 全景复盘

> 目标:拿到一个新想法,能自己拆解、让 AI 帮你写代码、跑起来、排错,最后做出成品。

---

## 一、先看清成品:这个项目是什么

**AI 私厨管家** —— 一个多模态食谱推荐应用:用户拍一张冰箱/厨房照片,AI 识别食材 → 联网搜食谱 → 从「营养 + 难度」打分排序 → 输出结构化推荐报告。

一句话拆成 4 个能力:

1. **看图** —— 多模态视觉模型(识别照片里的食材)
2. **联网** —— 搜索工具(找菜谱)
3. **推理** —— 大模型(打分、排序、组织语言)
4. **记忆** —— 数据库(记住多轮对话上下文)

```

│  (React+TS)  │  流式文本返回 │  app/server.py     │              │  create_agent     │
│  端口 3000    │ ◀────────── │  端口 8001         │ ◀─────────── │                   │
└─────────────┘              └──────────────────┘              └───────┬──────────┘
                                        │                              │
                                        │ 写读                         ├── 模型: qwen-vl-max (DashScope)
                                        ▼                              ├── 工具: TavilySearch (联网搜索)
                                 ┌──────────────┐                     └── 记忆: SQLite checkpointer
                                 │  SQLite 数据库 │
                                 │ checkpoint.db │
                                 └──────────────┘
```

**关键认知**:前端只负责「界面 + 转发请求」,真正的智能在后端。前端不知道什么是 Agent,它只是把文字和图片发给后端,接收流式文本。

## 四、后端代码逐块讲解(`app/server.py`)

后端是整个项目的灵魂,拆成 8 块:

### 1. 加载环境变量(密钥管理)

```python
load_dotenv(PROJECT_ROOT / "src" / ".env")   # server.py:49
```

- 密钥(`DASHSCOPE_API_KEY` 等)绝写死在代码里,放 `.env`,用 `dotenv` 读。
- 你的 `src/.env` 里就存了 4 个平台的 key。

### 2. 初始化模型(server.py:60)

```python
model = init_chat_model(
    model="qwen-vl-max",          # 视觉模型,能看图
    model_provider="openai",      # 走 OpenAI 兼容接口
    base_url=os.getenv("DASHSCOPE_BASE_URL"),
    api_key=os.getenv("DASHSCOPE_API_KEY"),
)
```

- `init_chat_model` 是 LangChain 的统一入口,一个函数适配各家模型(DeepSeek/Qwen/GPT…)。
- 这里选 `qwen-vl-max` 是因为它**支持图片输入**(纯文本模型如 `deepseek-chat` 不能看图)。

### 3. 定义工具(server.py:71)

```python
web_search = TavilySearch(max_results=5, topic="general")
```

- 这就是 Agent 的「手脚」:让模型能联网搜索。
- 工具本质是一个带**描述**的函数,模型读了描述就知道「什么时候该用它」。

### 4. 系统提示词(server.py:77)

```python
system_prompt = """
1.识别和评估食材:...
2.智能食谱检索:优先调用web_search工具...
3.多维度评估与排序:从营养价值和制作难度打分...
4.结构化方案输出:...
请严格按照流程...
"""
```

- 这是「给 AI 定规矩」的地方,决定了输出质量和行为。
- 你把业务流程写成步骤,模型就照着走。

### 5. 记忆(checkpointer)(server.py:96)

```python
async with AsyncSqliteSaver.from_conn_string(str(DB_PATH)) as checkpointer:
    agent = create_agent(model=..., tools=[web_search],
                          system_prompt=system_prompt,
                          checkpointer=checkpointer)
```

- `checkpointer` = 保存器,每次对话存一个「快照」,实现多轮记忆。
- 用 `thread_id` 区分不同会话(所以前端每次会话生成一个 UUID 当 `thread_id`)。

### 6. FastAPI 接口(server.py:206 起)

| 接口 | 方法 | 作用 |
|------|------|------|
| `/api/v1/oss/presign` | GET | 返回上传地址(模拟 OSS 预签名) |
| `/api/v1/upload/{filename}` | PUT | 存图片 |
| `/api/v1/chat/stream` | POST | **核心**:流式对话 |
| `/api/v1/chat/messages` | GET | 查历史 |
| `/api/v1/chat/messages` | DELETE | 清空历史 |

### 7. 多模态 + 流式(server.py:241 + 260,最重要的两段)

```python
# 把图片转成 base64 data URL,和文字一起塞进一条消息
content_parts.append({"type": "image_url", "image_url": {"url": data_url}})
content_parts.append({"type": "text", "text": text})
human = HumanMessage(content=content_parts)

# 流式:agent.astream 逐段吐出,边生成边返回
async for chunk, _metadata in agent.astream(
    {"messages": [human]}, config=config, stream_mode="messages"):
    if isinstance(chunk, AIMessageChunk) and chunk.content:
        yield chunk.content
```

- **多模态** = 一条消息里同时放 `text` 和 `image_url` 两种 part。
- **流式** = 用 `astream`(async stream)+ `yield`,让前端边打字边显示,不等全部生成完。

### 8. 图片压缩(server.py:134)

- 图片原图可能很大,直接转 base64 会浪费 token/超时。
- 所以先压缩到长边 ≤1024、转 JPEG、质量 60,再 base64。这是**成本意识**。

## 五、前端代码逐块讲解

前端 4 个核心文件,职责分明:

### 1. `lib/api.ts` —— 唯一跟后端说话的地方

- `API_BASE = "http://localhost:8001"`(写死后端地址)
- 5 个函数:拿上传地址、上传图、**流式聊天**、查历史、清历史。
- 流式的核心是 `fetch` + `response.body.getReader()` 逐段读:

```js
const reader = response.body?.getReader();
while (true) {
    const {done, value} = await reader.read();
    if (done) break;
    onChunk(decoder.decode(value, {stream: true})); // 每段回调
}
```

### 2. `app/page.tsx` —— 主逻辑(状态管理)

三个关键状态:

- `messages` —— 聊天列表
- `threadId` —— 会话 ID(存在 `localStorage`,刷新不丢)
- `processing` —— 是否正在生成(防止重复发送)

核心流程 `handleSend`:先上传图 → 添加用户消息 → 新建空助手消息 → 流式往里面塞文本。

### 3. `components/` —— 三个展示组件

- `ChatInput.tsx` —— 输入框 + 传图按钮(Enter 发送)
- `ChatMessage.tsx` —— 一条消息(用户靠右、助手靠左,支持 Markdown 渲染)
- `RecipeCard.tsx` —— 食谱卡片(展示分数、步骤、调料)

### 4. `types/chat.ts` —— TypeScript 类型定义

- `Message`、`Recipe` 等接口,让前后端数据结构有约定。

## 六、核心概念串起来:一次请求的完整旅程

用户上传照片点发送,发生了什么?

```
1. 前端 ChatInput 拿到图片 File
2. api.ts 先 PUT 到后端 /api/v1/upload,拿到图片 URL
3. 前端 POST /api/v1/chat/stream {message, image_url, thread_id}
4. 后端把图片 URL 读回本地 → 压缩 → base64
5. 拼成多模态 HumanMessage(文本+图片)
6. agent.astream() 开始跑:
   ├─ 模型(qwen-vl-max)看图 → 识别食材清单
   ├─ 模型决定「我需要搜索」→ 调用 web_search 工具
   ├─ 工具返回菜谱 → 模型再分析、打分、排序
   └─ 模型输出结构化报告
7. 后端逐段 yield,前端逐段 append 到助手消息
8. 整段对话被 checkpointer 存进 SQLite(按 thread_id)
```

**这段旅程里的每一个「模型决策」都是 LLM 自己做的**,代码只负责「搭桥」:把工具描述给模型、把工具结果还给模型、把输出流给前端。

## 七、从 0 到 1 的构建路线(7 个里程碑)

如果你要独立重做一遍,按这个顺序,每步都能跑、能验证:

| 里程碑 | 做什么 | 验证标准 | 涉及知识 |
|--------|--------|----------|----------|
| M1 | 调通模型 API(纯文本对话) | 控制台能 `invoke("你好")` | 环境变量、init_chat_model |
| M2 | 给模型加一个工具 | 问「北京天气」能调工具 | @tool、create_agent |
| M3 | 加系统提示词 + 结构化输出 | 输出固定格式 | prompt、BaseModel |
| M4 | 加记忆(多轮对话) | 第二句能记住第一句 | checkpointer、thread_id |
| M5 | 换成多模态模型,能看图 | 传图片能识别食材 | 多模态消息 |
| M6 | 包一层 FastAPI 接口 | 浏览器能 POST 到接口 | FastAPI、CORS |
| M7 | 加前端页面 | 网页能聊天、传图 | Next.js、React、流式 |

**核心思想:永远从「最小可跑」开始,一层层往上加,每一步都验证,而不是一次性写完整个系统。**

## 八、如何借助 AI 独立做出这类项目(方法论)

### 1. 正确的提问姿势(可直接套用的话术)

**别这么问**(太笼统):
> "帮我做个 AI 应用"

**要这么问**(有场景、有边界、有里程碑):
> "我想做一个识别冰箱食材并推荐菜谱的网页应用。请你帮我设计技术方案:后端用什么框架、大模型选哪个、要不要联网搜索工具、记忆怎么存。先只做第一步——调通模型 API,让它能识别一张图片并输出食材清单,给我可运行的代码。"

**三个万能模板:**

- **开新项目**:「我要做 X(一句话),面向 Y 用户,核心功能是 Z。帮我拆成 5 个能独立验证的小步骤,先实现第 1 步,给可运行代码。」
- **看不懂**:「这段代码的 XX 是什么?为什么这么写?用大白话讲,再举个类比。」
- **报错了**:直接把报错**原文**整段贴给 AI,附一句「我做了什么操作、期望什么结果」。

### 2. 迭代循环(做项目 = 循环这个)

```
想清楚要什么 → 让AI写代码 → 跑起来 → 报错/不对 → 贴错误给AI → 改 → 再跑
     ▲                                                        │
     └────────────────────────────────────────────────────────┘
```

**最关键的习惯:永远让「能跑」优先于「完美」**。先跑起来,哪怕丑、哪怕只有一句话回复,再一步步加功能。

### 3. 遇到报错怎么办(排错三板斧)

1. **看最后一行**:报错堆栈的最后一行通常才是真正原因。
2. **看类型**:是「缺依赖」(ImportError/ModuleNotFoundError)→ 装;是「配置错」(认证失败、key 无效)→ 查 .env;是「类型/语法」→ 让 AI 看代码。
3. **贴给 AI 时带上下文**:「我在 Windows 上、用 uv 装的依赖、报错是下面这段」——上下文越全,AI 越准。

### 4. 哪些「交给 AI」,哪些「必须自己懂」

- **可以放心交给 AI 的**:前端样式(Tailwind 类名)、模板代码(FastAPI 路由骨架)、环境配置。
- **你必须自己懂的**(否则做不出下一个):`Agent=模型+工具` 这个心智模型、`多模态消息`怎么拼、`流式`和`记忆`怎么实现、`系统提示词`决定行为。这四条就是你项目的「灵魂」,换任何项目都能复用。

## 九、一句话总结

> **一个 AI 应用 = 大模型(会想)+ 工具(能做)+ 提示词(定规矩)+ 记忆(能记)+ 接口(能交互)+ 界面(能用)。**
> 你把这个公式套到「天气助手」「学习搭子」「代码审查」任何一个新想法上,让 AI 帮你逐步实现,就是「独立借助 AI 做出项目」。
